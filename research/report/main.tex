\begin{abstract}
Texloom is a Windows prototype that translates selected edits to compiled
\LaTeX\ text into constrained changes to the original source. The primary
operation is single-page text displacement that retains the fragment's
contribution to document flow. Source evidence, private identity probes,
immutable compilation, independent PDF inspection and revision-bound commit
form a chain of checks. Replacement, semantic parameter changes and legacy
positioned blocks have different acceptance policies and must be evaluated
separately. This technical report documents the implemented mechanism, the
limits of its checks, recorded development evidence and a proposed fixed-version
evaluation. Two component pilots are reported with explicit entry layers.
A native candidate-boundary pilot met declared source, render and Undo
conditions for five intended moves and refused 25 corrupted source packets;
an initial invalid reference and its failed run are retained. These purposive
development cases do not estimate full-app error frequency. No final held-out
evaluation, native latency distribution or unassisted usability study has run.
No novelty, universal correctness or publication-readiness claim is made.
\end{abstract}
