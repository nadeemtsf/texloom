\section{Recorded development evidence}
\label{sec:development}
This section reports executed development work with its scope intact.
Engineering checks, post-compilation predicate replay and native candidate
entry are different evidence types. Their counts are not summed into an
application accuracy denominator. The final held-out set remains unused.

\subsection{Source-coordinate and paragraph-intent development checks}
At \code{5ca1eb6}, the required default core run passed 70 unit, 18 pre-existing
integration, 13 position-map, 8 intent-plan and 19 source-projection checks.
These overlapping engineering layers are not independent document samples or
an edit-acceptance denominator. The position tests include a tagged-character
splice oracle: original tags distinguish repeated/equal text from inserted
text, and expected preserved ranges are derived without the implementation's
coordinate-delta formulas. Unicode checks concern exact source/editor
boundaries, not shaped output or actual Arabic/Hebrew caret behavior.

Three pre-fix tests reproduced incorrect selection retention after a prefix
insertion, selected-content deletion and partial destruction of a multi-range
selection. Their failed run is preserved. A later test showed that escaping
backslash/tilde/caret input could make the candidate unrecognizable on the next
projection; exact standard literal-command recognition fixed this case, while
malformed/nonempty terminators remain unsupported. A recovery-test fixture
that assumed a replaced selection survived was corrected to inject its invalid
BOM boundary explicitly; recovery rejection was not weakened. The dated
engineering receipt binds these runs and their limitations.

A separate fixture bridge at \code{479f826} used the actual read-only planner
to generate replacement/deletion source. All nine external compile/text checks
passed: baseline, replacement and deletion for one English document under each
of pdf\LaTeX, Xe\LaTeX\ and Lua\LaTeX. Normalized extracted document text matched
the independently declared expectation, including the replacement's ampersand
and percent; the original fixture remained byte-identical. This reused case
checks compilation and text portability, not glyph geometry, unrelated-render
preservation under general reflow, RTL rendering or a held-out success rate.
It bypasses application PDF selection and native visual acceptance.

Separately, 20 headless native document/recovery checks passed at the preceding
planner snapshot; one verifies UTF-16 selection replies, repeated-occurrence
retention and Undo/Redo after a Unicode prefix edit. The unchanged frontend
suite passed 291 checks. These are not Windows input observations. The prepared
r8 application was not rebuilt, opened or installed for this work, and final
evaluation remains unfrozen/unrun.

\subsection{The failed reference is part of the result}
The first attempt recorded zero of five intended moves meeting every declared
postcondition. All five native commits, exact-source checks and Undo checks
completed; all 25 corrupted packets were refused with a native operation-plan
mismatch. The moved-reference comparisons failed because the manually authored
gold changed unrelated layout.

The zero-width reference box began in vertical mode. Its following phantom
started another blank line. The intended target moved the correct 12 bp, but
the gold's following neighbor moved down about 11.955 bp for Latin or
11.956 bp in the multilingual conditions. Native candidate geometry retained
the neighbor. Gold-only comparisons of the zero and moved references reproduce
this error without consulting native output; a rendered pair was also inspected.

The original protocol, executed-source snapshots, zero/five count, PDFs and
comparison failures are unchanged. The failure is not retrospectively labelled
a full application correctness pass, nor is the invalid gold treated as proof
that the application accepted a wrong edit. A diagnosis was stored separately.

Before another attempt, reference protocol revision 2 added \code{leavevmode}
before the TeX box and a reference-only geometry health check. The declared
second-occurrence words must move exactly; every other word bound must stay
within 0.02 bp. Missing or reordered/ambiguous words remain unresolved. This
health check is bounded word geometry, not a proof of every reference semantic
or non-text property.
