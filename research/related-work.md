# Related-work notes - first primary-source pass

Checked 4 November 2026. This is a scoped first pass, not an exhaustive novelty search. Bibliography entries correspond to the versions actually inspected. Summaries are deliberately short; claims about other systems' failure rates or guarantees require experiments or explicit specifications.

| Source | Verified point and relevance | Consequence for Texloom |
| --- | --- | --- |
| Laurens, [SyncTeX parser API](https://github.com/jlaurens/synctex/blob/04cf8e3e8665ff203248d7af78ee1129afbc1b64/synctex_parser.h), Query section; [author README](https://github.com/jlaurens/synctex/blob/04cf8e3e8665ff203248d7af78ee1129afbc1b64/synctex_parser_readme.txt) | Source/display queries can return multiple nodes; exact columns may fall back to lines, and PDF forms can be ambiguous. The API documents synchronization, not source-update correctness. | Treat SyncTeX as evidence, then test a proposed source fragment. Do not claim that synchronization alone makes edits safe. |
| Foster et al., [Combinators for Bi-Directional Tree Transformations](https://www.cs.cornell.edu/~jnfoster/papers/lenses.pdf), POPL **2005** version, Section 3 | Defines get/putback and round-trip laws. The inspected 14-page PDF is the conference version, not the 2007 expanded journal article. | Useful conceptual language for view updates. Texloom has no proof that arbitrary TeX/PDF behavior satisfies lens laws. Exact Undo is a different property. |
| Mayer, Kuncak and Chugh, [Bidirectional Evaluation with Direct Manipulation](https://arxiv.org/abs/1809.04209), OOPSLA 2018, DOI [10.1145/3276497](https://doi.org/10.1145/3276497) | Updates programs from manipulated output using an evaluation-update algorithm, with custom lenses. | Output-to-source interaction already exists. Texloom uses bounded TeX source plans and compiled-output checks rather than reversing a general TeX evaluator. |
| Hempel, Lubin and Chugh, [Sketch-n-Sketch: Output-Directed Programming for SVG](https://jlubin.net/assets/uist19.pdf), UIST 2019, DOI [10.1145/3332165.3347925](https://doi.org/10.1145/3332165.3347925) | Combines source and graphical interaction, with provenance and output-directed operations. | This is close conceptual prior work. A potential contribution is evidence about preservation/refusal in the LaTeX setting, not inventing direct manipulation. |
| [LyX official description](https://www.lyx.org/) | A graphical, structure-oriented document processor using TeX/LaTeX. | Do not claim that graphical scientific authoring or LaTeX-backed editing is new; native-format/workflow differences preclude an unqualified timing comparison. |
| van der Hoeven, [GNU TeXmacs: A free, structured, wysiwyg, technical text editor](https://www.texmacs.org/joris/gut/gut.pdf), PDF dated 10 December 2008 | Discusses structured scientific editing and high-quality interactive typesetting. | Related interface goals, not evidence that Texloom outperforms it or supports the same document model. |
| [BaKoMa original distribution README archived on CTAN](https://ctan.org/tex-archive/systems/win32/bakoma?lang=en), 2011 snapshot | Describes TeXWord editing LaTeX sources through a rendered-page interface. | Especially important prior visual-LaTeX work. Availability, internals and preservation guarantees have not been independently assessed; no superiority claim. |
| [Overleaf editor documentation](https://docs.overleaf.com/getting-started/how-do-i-use-overleaf) and [PDF/source navigation](https://docs.overleaf.com/navigating-in-the-editor/working-with-the-pdf-viewer/editor-and-pdf-layout-and-sizing) | Distinguishes code/visual editors from compiled PDF preview and SyncTeX navigation. | Interface modes are not equivalent to a verified PDF displacement contract. Documentation alone cannot prove the absence of an internal technique. |
| Pnueli, Siegel and Singerman, [Translation validation](https://link.springer.com/chapter/10.1007/BFb0054170), TACAS 1998 | Checks individual translations, with an explicit semantic/refinement framework. | A useful analogy for checking each candidate. Texloom's finite geometric/raster checks are not their formal refinement proof. |
| Tilmann, [latexdiff](https://ctan.org/pkg/latexdiff?lang=en) | Marks significant differences between LaTeX sources for review. | Source review is complementary; it does not by itself certify unchanged rendered content. |

The publisher PDF for Laurens' 2008 TUGboat article could not be fetched reliably in this session. Its search-visible bibliographic record is a lead, not a substitute for a full-text review. The report instead cites the inspected author-maintained API for the concrete synchronization limits above. No claims are based on Reddit, third-party product summaries or unverified citation counts.

Next useful literature work: inspect the expanded lenses paper; search backward/forward citations from the two Sketch-n-Sketch papers for document-specific update verification; inspect original BaKoMa documentation before designing any competitor study. Record exclusions and retrieval limitations. Product marketing is not proof of a correctness contract, and absence of a claim in documentation is not proof that a feature is absent.
