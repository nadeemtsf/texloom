# Preliminary desktop preview validation

Record before the native transport diagnostic. Extend the existing first-pass
library observer with optional raw Tauri channel delivery and a separate
read-only current-page canvas. The settled result remains the only source of
build identity, mapping, verification, pinning and export authority.

The logical progress DTO binds schema, phase, project, revision, request ID
and actual engine. It has no build ID or verification flag. The client rejects
wrong identities, unknown fields and cross-use with final replies. Its channel
owns an opaque per-invocation ticket, so reopening the same project/revision
cannot admit an older callback with coincidentally equal visible IDs.

Verify the full native Backend on a fresh synthetic article: canonical preview
gets exactly one event and preserves source/history; export and prepared visual
builds get no event even when a callback is supplied. Save the early and final
PDFs and parse/render them. This headless check exercises service routing and
does not test actual WebView dispatch.

Automated UI checks cover optional failures, duplicates, cancellation, pending
render disposal, final publication, source edits and old-ticket races. Paint a
real PDF through the temporary renderer. The original settled PDF must remain
alive until final publication, and temporary views must never pin or verify a
build. Run the complete local gate and applicable exact-head GitHub checks.

Produce a named portable development candidate. Owner-run acceptance is required
before merging this visible feature: preliminary label/read-only behavior,
settled catch-up, cancellation/failure retention, typing/project switching,
scroll/resize/focus, and existing selection/edit/Undo/Save/reopen behavior.
No agent app control or installation. Earlier component timing data remains
separate; this phase makes no physical-presentation or application-speed claim.
