## Consequence for the question

The provisional question accurately describes Texloom's engineering problem, but is too broad to function as a novelty claim. A narrower empirical question is:

> For declared single-page LaTeX text-displacement requests, how do constrained source plans and checks after compilation affect incorrect acceptance, useful acceptance/refusal, unrelated-content preservation and execution cost?

This is an investigation target, not an achieved contribution. Source evidence, candidate derivation, independent inspection, native commit, display and Save must have separate observations. Different contract families remain separate. No existing evidence justifies claiming a new bidirectional theory, formal correctness, a generally superior editor or publication readiness.

The most useful next comparison must distinguish errors rejected before compilation from checks that actually reach a compiled candidate. The existing 25 corrupted source packets all fail source rederivation; they cannot measure the independent renderer's marginal value. Matching/identity failures, semantically wrong but internally consistent requests and downstream PDF corruptions need separately labelled entry layers and independent expected outcomes. See `ADJUDICATION.md` for the proposed annotation procedure. No such new comparisons have run.
