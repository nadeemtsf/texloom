# P6 independent comparison checkpoint

`texloom-build::verification` implements a UI-independent comparison over trusted PDF inspection evidence. It is deliberately not a native commit authorization API. The existing application still uses its previous PDF.js validation; packaged PDFium inspection and receipt-bound native authorization remain open.

The comparison checks every physical page, exact text multiplicities, target membership, uniquely matched glyph geometry, unchanged non-text object geometry and every rendered pixel. It compares bounds within the same renderer. Target tolerance is 0.25 bp; unaffected and identity glyph tolerance is 0.02 bp; non-text geometry uses 0.000001 bp. Identity still requires exact pixels. The frontend cannot change these tolerances. Extraction order may change, but ambiguous correspondence is refused. Successful results report their maximum geometry error.

For a supported displacement, it reconstructs the complete expected image from the baseline: erase isolated target glyph windows onto opaque white, then translate their original pixels. Source and destination windows must avoid unselected text and non-text objects in both snapshots. This checks changed target appearance, the vacated area, the destination and all other pixels. It does not merely ignore two rectangles, which could hide duplicate ink. This policy requires a producer with complete paint/object coverage and a pinned white-background render configuration.

Current restrictions are explicit: zero-origin full-page crops, zero rotation, no annotations, a single-page target, supported positive glyph bounds, and integer-pixel shifts at the inspected scale. Fractional-pixel appearance, arbitrary page coordinate adapters, overlapping/colored backgrounds and unsupported paint require stronger adapters. This is not a full native drag acceptance claim. UserUnit validation remains part of the existing PDF.js fixture inspector; the future independent worker must establish its own coordinate contract.

Budgets bound page/object/raster sizes, matching work and target isolation work. Nonfinite geometry, truncated buffers, changed formats, ambiguous identity and exhausted budgets are errors. Thirteen focused Rust tests include the duplicate-ink regression, repeated/coincident text, target/neighbor changes, overlap, annotations, multiple pages, unsupported coordinates, malformed buffers and bounded floating-point noise with exact pixels.

The first engine run (41492602048 at e71c283) failed the proposed 0.000001 bp identity glyph threshold under pdfLaTeX and two XeLaTeX cases, while all LuaLaTeX cases passed. It is retained in docs/evidence/displacement-policy-first-run.json. The corrected comparison uses the already established 0.02 bp unchanged-glyph threshold for identity too, while preserving exact full-raster equality. A regression test proves that bounded numeric noise cannot excuse any changed pixel. The next CI run must report the measured maxima and pass the corpus before acceptance.

The development `displacement_check` bridge consumes the pinned PDFium 126.0.6462.0 / pypdfium2 4.30.0 fixture output. It checks PDF and raster SHA-256 receipts, bounds file reads, and confines raster paths to their evidence directory. Its target record IDs come from the explicit fixture oracle, never application users. This old development pin is not a decision to ship it as a runtime dependency. CI runs it alongside the existing JavaScript oracle on the three-engine movement corpus and requires it to reject the retained broken-literal PDF for a geometry/appearance reason. A real-PDF identity smoke check must pass first, so an absent executable or bad receipt cannot count as successful regression rejection.

Before connecting this to `document_commit`, P6 still needs a packaged isolated worker, independently established target provenance, complete text/paint/annotation coverage, build/project/revision/operation binding, cancellation and failure handling, support for ordinary drag deltas, and the actual native signature select/move/edit/undo/save/reopen scenario. Native typing/IME/mouse access is currently denied. P7-P9 acceptance gates remain open.
